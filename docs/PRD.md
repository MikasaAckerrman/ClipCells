# ClipCells — локальные ячейки быстрого копирования

## Goals
Создать полностью офлайн Android-приложение, где пользователь хранит неограниченное число именованных ячеек-папок. Короткое нажатие последовательно записывает все сообщения ячейки в системный буфер, а удержание 2,7 секунды открывает выбор отдельных сообщений. Работа очереди продолжается после сворачивания приложения и видна в системном уведомлении.

## Requirements
- [ ] При первом запуске ячеек нет; `+` открывает редактор.
- [ ] Ячейка требует непустое имя и хотя бы одно непустое сообщение; количество и длина программно не ограничиваются.
- [ ] Короткое нажатие копирует сообщения сверху вниз с интервалом 1 с; диапазон настройки 0,3–3 с.
- [ ] Удержание 2,7 с имеет визуальный прогресс и вибрацию, затем открывает сетку сообщений 3×3 с вертикальной прокруткой.
- [ ] Выбор сообщений нумеруется в порядке касаний. `Копировать` при пустом выборе только закрывает окно; иначе закрывает окно и запускает очередь.
- [ ] Foreground service продолжает очередь в фоне, показывает `N из M`, позволяет отменить; новая очередь заменяет текущую.
- [ ] Главная сетка по умолчанию 2×3; настройки: 2–5 столбцов и 3–8 видимых строк.
- [ ] Карандаш включает редактирование и перестановку; корзина включает множественный выбор, подтверждение и Undo на 5 секунд.
- [ ] Редактор поддерживает имя, сообщения, порядок, цвет, значок, интервал и восстановление черновика.
- [ ] Экспорт/импорт включает ячейки, сообщения, порядок и настройки; режимы merge/replace, страховочная копия перед replace.
- [ ] Опциональная PIN/биометрия выключена по умолчанию.
- [ ] Нет INTERNET permission, аккаунтов, рекламы, аналитики и сетевых зависимостей.

## Non-Goals
- Не читать и не очищать историю Gboard.
- Не закреплять записи в Gboard: Android не предоставляет такого API.
- Не гарантировать, что Gboard сохранит каждую промежуточную запись: приложение гарантирует отдельные вызовы ClipboardManager, итог проверяется на целевом устройстве.
- Нет синхронизации, облака, веб-версии и собственной клавиатуры.

## Constraints
- Цель: iQOO Neo 10, OriginOS 6 / Android 15, Gboard, ru-RU.
- Android 14+ требует объявленного типа foreground service; используется `specialUse` с описанием назначения.
- В PRoot нет Android SDK: JVM-ядро тестируется локально, Android-модуль собирается в GitHub Actions, поведение ClipboardManager/Gboard проверяется на устройстве.
- Foreground service запускается только явным действием пользователя из видимой Activity.

## Approach
Kotlin + Jetpack Compose, Room для данных, DataStore/Preferences для настроек, отдельный чистый JVM-модуль для правил очереди. Android-служба получает неизменяемый снимок очереди, заменяет предыдущую задачу, пишет каждый элемент отдельным ClipData и обновляет notification. UI наблюдает Room Flow; удаление обратимо до истечения Snackbar.

## Open Questions
Нет блокирующих продуктовых вопросов. Имена приложения, иконка и финальная палитра могут быть выбраны на этапе полировки.
